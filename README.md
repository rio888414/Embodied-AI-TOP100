# 智元精灵 · 具身智能 TOP100 合作

由 **智元机器人** 打造的全球具身智能公司融资追踪平台，面向投资机构、行业研究者与创业者。

实时聚合全球具身智能公司的融资动态、估值与轮次信息，以「**估值优先、融资额兜底**」的规则自动生成权威排名，并为每家公司标注一句话核心竞争力。与智元机器人有合作的公司以**青色「智元生态」**标记凸显，智元本体以**金色「本平台」**标记。每日新进与排名上升的公司以**橙色 NEW / 金色 ↑N** 徽章标注（下降不标注）。

**当前规模**：128 家公司 / 83 条融资事件（导出日期 2026-10-09），覆盖本体层 60 · 模型层 43 · 基建层 25。其中**智元生态伙伴 11 家**，估算估值 70 家，累计融资合计 **2542.6 亿元**。

> **收录范围**：平台自 v2.2 起只收录**三层** —— 本体层 / 模型层 / 基建层。
> **零件层（灵巧手、关节模组、减速器、传感器、电机等零部件厂商）已整体移除**，公司、介绍、事件与统计均不再包含。

## 一、核心机制：估值优先排序

排名规则严格如下，不可变更：

1. 优先按 **估值**（`valuation_cny_yi`）降序排列；
2. 估值缺失的估算公司，按 **累计融资金额** 折算的估算估值降序排列；
3. 两者皆缺失者，排在**末尾**；
4. 金额与估值保留原始币种（美元 / 人民币 / 欧元），同时存储统一折算额，折算口径为**人民币亿元**，排序与图表一律使用折算额，前端同时展示原始币种；
5. 港股 / 美股 / A 股上市公司使用市值或发行估值，标注「已上市」。

榜单页在表格上方明示该规则：`排序规则：按估值降序 · 估值未披露的公司按累计融资额降序排列 · 金额统一折算为人民币亿元`。排序逻辑**完全透明可验证**。

> **注意**：榜单**不提供**「按融资额排序」切换；估值榜始终以估值优先，保证跨公司可比性。同时平台**不再保留历史快照视图**，只呈现当前时点的权威榜单。

### 估值估算规则（针对未披露估值公司）

市场中大量具身智能初创公司（如原力灵机、章鱼动力、地瓜机器人等）并未披露投后估值，但融资轮次与金额公开。为使其可纳入统一排名，平台按以下规则估算：

> **未披露估值的公司，按「累计融资额 × 倍数」估算，倍数随轮次递进：种子/天使 5x、A 轮 6x、B 轮 7x、C 轮及以上 8x。**

- 估算结果写入 `valuation_cny_yi`，同时 `valuation_is_estimated = true`；
- 前端以**金色**区分估算值与披露值，鼠标悬停显示 `valuation_note` 中的估算口径说明；
- 当前 128 家中有 **70 家**为估算估值，其余 58 家为披露值（含上市公司市值）。

## 一之二、核心竞争力标注

榜单每行新增「**核心竞争力**」列，为每家公司提供约 **20 字**的一句话核心竞争力/产品介绍：

- 字段：`core_advantage`（约 20 字核心竞争力描述）+ `core_product`（核心产品名，金色小字附于其下）；
- 覆盖：128 行**全部有内容**，无空值，平均长度约 20.7 字；
- 用途：让读者在扫榜时一眼看懂「这家公司强在哪」，而非只看估值数字。

### 视觉规则（为什么用青色）

平台里**金色已被占用**——它同时表示「已上市」和「估算估值」，属于**数值属性**。
生态关系属于**归属属性**，若也用金色会造成语义混淆。因此：

- **青色 `--partner`（#3FB8C4）** 专用于生态关系，色值取自已移除的零件层色板，视觉得以复用；
- 语义分工：**金 = 数值属性**（上市 / 估算），**青 = 归属属性**（生态合作）。

具体表现：

- 榜单行：**整行外框**（青细描边 + 圆角）框出生态伙伴行，首列 3px 发光关系条；
- 公司名后跟**青色描边胶囊**徽标（发光圆点 + 不填充）；
- 领奖台、赛道下钻卡片同步描边外框与关系圆点；
- 表头下方**图例**说明标记含义 + 伙伴数量 + 变化标记；
- 统计条含「智元生态伙伴」一项（青色）。

> **v2.4 二次调整（外框化）**：首版采用「青色渐变行底 + 实心渐变胶囊」，反馈「一整排一块一块的渐变色」视觉过重。
> 现改为**外框方案** —— 用首尾单元格描边模拟一条完整的矩形框把该行框出来，行内不出现任何块状渐变色；
> 徽标同步改为**描边胶囊**（不填充），把「色块」这一视觉权重整个让给 NEW 标签。

### 「仅看生态伙伴」开关

榜单图例右侧提供切换按钮，可一键切到**生态视图**（11 家伙伴）。

> **名次语义**：生态视图下**保留全量榜的真实名次**（如数字华夏显示 #98，而非重新编号成 #11），
> 避免误读为「生态伙伴都排在前列」。排序规则与全量榜完全一致。

## 一之四、每月变化标记

榜单需要回答一个问题：**这个月有什么新变化？** 平台用两个字段表达，并遵循一条非对称规则。

### 数据字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `daily_change` | TEXT | `'new'`（本月新进 / 有新融资）/ `'up'`（排名上升）/ `'down'`（排名下降）/ `null`（无变化） |
| `daily_change_value` | INTEGER | 仅 `up` 有意义，表示**上升的位次数** |

### 显示规则（非对称）

> **只标注「新进 / 有融资增长」与「上升」，顺位下降的公司不标注。**

- `new` → 橙色描边标签 **NEW**（全站唯一橙色）；
- `up` → 金色标签 **↑N**（N 为上升位次）；
- `down` 与 `null` → **不显示任何标记**。

设计理由：榜单的核心叙事是「谁在冒头」。下降是常态且数量庞大，若全部标出会淹没真正的新增信号；
而新进与上升是**值得被看见的增量**，应单独成通道。

### 窗口口径

NEW 采用**近 30 天滚动窗口**，判定依据是「公告日在窗口内的融资事件」：

- 口径同时覆盖两类变化 —— **本期新收录的公司**（如小鹏机器人）与**已有公司拿到新轮次**（如地瓜机器人 C 轮）；
- 每天更新时窗口自动前移，无需人工维护；
- 当前窗口（截至 2026-10-03）截止日为 **2026-09-03**，命中 **9 家**：

## 二、数据口径

> **重要**：本平台对「公司估值」与「累计融资额」两个字段做**严格区分**，二者绝不混用。
> `valuation_cny_yi` 只存公司估值（一级市场投后估值 / 二级市场市值 / IPO 发行估值），
> `total_funding_cny_yi` 只存公司历史累计融资总额。任何一行若把融资额填入估值列，都视为数据错误。

### 纳入范围（三层分层）

> 平台自 v2.2 起将收录范围收敛为**三层**，**零件层整体移除**（不再收录灵巧手、关节模组、减速器、传感器、电机等零部件厂商）。

| 分层 | 覆盖内容 |
|---|---|
| 本体层 | 人形机器人、双足 / 四足机器人整机 |
| 模型层 | 具身大模型、VLA 模型、世界模型、机器人操作策略 |
| 基建层 | 运动控制、仿真平台、数据采集与遥操作、具身数据平台 |

### 明确排除

**零件层（灵巧手与末端执行器、关节模组、减速器、力/触觉传感器、机器人电机等零部件厂商）**、
工业自动化产线、AGV/AMR 物流小车、无人机、自动驾驶乘用车、扫地机、纯机器视觉。

## 三、真实性红线

1. **无明确信源的事件不得收录**，宁可少收录，绝不编造。
2. 信源优先级：官方公告与监管披露 > 企查查等工商登记数据 > 权威财经媒体 > 其他第三方数据平台。
3. 估值口径冲突时**不自行择一**，保留多口径并在前端标注来源，或标为「未披露」按累计融资额排序。
4. 模糊金额（「数亿元」「近亿元」）保留原文，另设估算值字段，前端用**金色**区分披露值与估算值。累计融资额与单轮金额分列，严禁混计。
5. 未披露金额记 `null`，禁止用 0 或猜测值填充。
6. **估值与融资额分列校验**：`valuation_cny_yi` 只存估值，`total_funding_cny_yi` 只存累计融资，禁止互相填充。每次数据更新后须交叉核对权威榜单（RobotHub 全球人形机器人估值榜、胡润全球独角兽榜等）。

## 四、视觉设计

### 设计语言：Obsidian Financial Terminal

界面采用金融终端质感的暗色设计系统，以**信息层级**而非线框来建立秩序：

- **色彩**：黑曜石多层深灰（5 层背景）为底，香槟金（三档）作强调，配数据语义色（涨红 / 跌绿 / 分层三色）。
- **层级**：靠字重、字号、透明度三重梯度建立秩序，避免满屏边框线。极细描边（`--line`）+ 内发光 + 渐进蒙版营造质感。
- **节奏**：大留白分区与紧凑数据区交替，形成呼吸感。
- **领奖台**：前三名独立卡片，各带名次氛围光球与估值对比条。
- **名次强度条**：榜单行首 3px 色条，透明度随估值强度递减，前 3 名金色。
- **氛围光**：全局两组极淡径向渐变，避免纯色块死板。

### 榜单表头的对齐契约

榜单是信息密度最高的区域，对齐靠一套**单一数据源**的列宽契约保证：

- `index.html` 用 `<colgroup>` 定义 8 列宽度（`w-rank` / `w-company` / `w-core` / …），
  配合 `table-layout: fixed`，使**表头与每一行数据共用同一套列宽**，从根上杜绝错位；
- 对齐按列语义分工：**文本列左对齐**（#、公司、核心竞争力、领投方）、
  **数值列右对齐**（估值、累计融资，并额外留 `padding-right: 22px` 避免贴边）、
  **枚举列居中**（最新轮次、地区）；
- 表头独立成带：`--surface-2` 底色 + `--line-strong` 下边线 + 胶囊化字距，与数据区形成清晰分界；
- 长文本列（核心竞争力）限制 2 行并省略，行高恒定；公司名、领投方单行省略，防止长短不一撑破列宽。

改列宽只需动 `colgroup` 与 `:root` 两处，无需逐列调样式。

### 生态关系的视觉通道

颜色按**属性类别**分工，避免语义打架：

| 色 | 属性类别 | 用途 |
|---|---|---|
| 金色 `--gold` | 数值属性 | 已上市、估算估值、**排名上升 ↑N** |
| 青色 `--partner` | 归属属性 | 智元生态伙伴 |
| 橙色 `#E8954C` | 时间属性 | **本月新进 / 有新融资 NEW** |

区分靠**整行外框 + 首列 3px 发光关系条**，而非满屏描边或块状填充——与「靠层级而非线框建立秩序」的整体设计语言一致。
所有标记统一为**描边胶囊**（不填充色块），保证在密集表格里可被扫到，同时不制造视觉噪音。

**变化标记**沿用「属性类别」的分色逻辑：**橙色 = 时间属性**（这个月新来的）、**金色 = 数值属性**（位次变化的幅度），
与既有语义不冲突。

> **色块收敛原则**：v2.4 二次调整把行内所有块状渐变色全部去掉 ——
> 生态伙伴靠「外框」表达归属，NEW / ↑N 靠「描边标签」表达变化，表格里不再出现争抢注意力的小色块。

> 徽章容器 `.co-name` 为 `flex-wrap: wrap`，公司名过长时徽章自动换行而非被挤出可视区。

设计变量集中在 `styles.css` 顶部的 `:root`，改色只需改一处。

## 六之二、批量导入接口

为避免逐行 INSERT，云端提供两个批量装载函数：

```sql
CREATE OR REPLACE FUNCTION load_companies(payload jsonb) RETURNS integer ...
CREATE OR REPLACE FUNCTION load_events(payload jsonb)    RETURNS integer ...
```

用法（单次可传 4–5 个对象组成的 JSON 数组）：

```sql
SELECT load_companies($1::jsonb);   -- $1 为公司对象 JSON 数组
SELECT load_events($1::jsonb);      -- $1 为事件对象 JSON 数组
```

**关键约束与经验**：

1. `companies.id` 为 `GENERATED ALWAYS`，INSERT 时**不可显式写 id**，函数已省略该列；
2. 通道对 `$$ ... $$` 美元引号不稳定，推荐改用 `$fn$` 等其他标签；**传参推荐使用绑定参数
   `$1::jsonb` + 参数数组**，避免手工转写 base64 —— 长 base64（>1KB）人工转写极易引入
   静默字符错误，报 `not valid UTF-8` 或 `illegal base64 data`；
3. `funding_events.event_fingerprint` 建议格式 `公司名|轮次|公告日期`，作为去重依据；
4. 大批量写入后务必核验总数与去重数：

   ```sql
   SELECT count(*), count(DISTINCT name_cn) FROM companies;
   SELECT count(*) FROM funding_events;
   ```

```sql
  '某某科技', '某某科技|A轮|2026-10-01', 'A 轮', '数亿元人民币', true,
  3, '2026-10-01', '中国', '模型层',
  '某某资本', '某某创投', false,
  NULL, '一句话业务亮点', 'https://信源链接', 'verified'
);
```

**关键点：**

- `event_fingerprint` 必填，格式为 `公司名|轮次|公告日期`。这是**去重的唯一依据**，同日同轮次重复写入会被识别为同一事件。
- 若该公司同时需要出现在估值榜，还要更新 `companies` 表对应行的 `latest_round`、`latest_round_amount_text`、`total_funding_cny_yi` 等字段。
- 模糊金额（「数亿元」）务必把原文写进 `amount_text`，同时把 `amount_is_estimate` 设为 `true`，前端会自动用金色标注。

使用 `daily-update.md` 中的提示词，让 WorkBuddy 自动检索、整理并写入。
